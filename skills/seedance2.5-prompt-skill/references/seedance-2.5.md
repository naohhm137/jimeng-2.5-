# Seedance 2.5 增量（相对 2.0）

> **状态**：2026-08-07 建档。基于官方发布通稿 + 三份第三方实测，**尚无本地 case 验证**。
> 标 🔬 的条目是"看起来成立但我们没亲手验过"，跑过之后回来把结论坐实或推翻。
>
> **本文件只写 2.5 与 2.0 的差异。** 相机四维编码、美学约束、剪辑节奏、图片生成、路径 C 双范式、
> 版权审查 SOP 等方法论全部继承 2.0，见 SKILL.md 与对应 references。

|:---|:---|

## 1. 硬参数变化

| 项 | 2.0 | 2.5 |
|:---|:---|:---|
| 单次生成时长 | 15s | **30s** |
| 平台侧延长 | 分段生成 + 延长拼接 | 即梦/小云雀**支持 2 次延长 → 最长 90s** 🔬 |
| 超长模式 | 无 | 即梦端**长视频模式，单次直出最长 180s** 🔬 |
| 参考素材总数 | 12（图 ≤9 + 视频 ≤3 + 音频 ≤3） | **50（图 ≤30 + 视频 ≤10 + 音频 ≤10）** |
| @引用编号上限 | `@图片1~9` `@视频1~3` `@音频1~3` | **`@图片1~30` `@视频1~10` `@音频1~10`** |
| 编辑能力 | 视频延长 / 元素替换 | 新增**时间戳编辑、绿幕编辑、视角编辑、参考编辑** |
| 片段重拍 | 无 | 框选时间段 + 画面区域 + 提示词，**单秒级修改** |
| 特殊素材 | — | **绿幕 / 白模**可作参考；可接 Maya / Blender 插件 🔬 |
| 画质 | — | 画质/音质/运动质量优化，官方称**弱化了"油腻感"** |

**"油腻感"这条要当心**：如果 2.5 原生就弱化了塑料感，2.0 时代那套堆砌
`Octane / 8K / 工业光魔 / 杜比视界` 的美学约束**可能从"有用"变成"多余甚至有害"**
（参考 SKILL.md 里黑神话那条经验：新一代模型 prompt 越短越有效）。
🔬 **这是 2.5 最值得第一批实测验证的假设**：同一条概念，一版带完整美学约束、一版极简，对比出片。

## 2. 方法论级变化：30 秒直出推翻了路径 B 的核心假设

2.0 时代 SKILL.md 写的是「单次生成上限 15 秒，超出需分段拼接」。2.5 下这句对 ≤30s 不再成立，
而且**直出和拼接不是同一件事的两种做法，是质量上的本质区别**。实测原文：

> 拼接的问题是每段衔接处都有一致性损耗，人物换脸、光影跳变。
> **30 秒直出是一次推理生成的连续叙事，人物、场景、镜头语言从头到尾是同一套。这是本质区别。**
> —— [优设网 Seedance 2.5 实测](https://www.uisdc.com/seedance-2-5-2)

### 路径 B 的新决策树

| 目标时长 | 2.5 下的做法 | 还需要拼接吗 |
|:---|:---|:---|
| ≤30s | **单条提示词 + 时间戳分镜，一次直出** | ❌ 不需要 |
| 30–90s | 直出 30s + 平台侧延长 ×2 🔬 | ❌ 不需要剪辑软件 |
| 90–180s | **长视频模式单次直出**，全部剧情写在同一条提示词里 🔬 | ❌ 不需要 |
| >180s | 才回到 2.0 的分段生成 + 拼接 + 剪辑公式 | ✅ 需要 |

**连带失效的旧结论**（在 2.5 下要限定适用范围）：

- ❌「不要在 15 秒里讲故事，≤15 秒的本质是一个不可能的瞬间」
  → **这条仍然对 ≤15s 成立**，但 30s 起就该真讲一个起承转合了
- ❌「≥45 秒推荐走 25 格制作流水线」
  → 2.5 下 45s 落在"延长"区间，25 格流水线的门槛应上移到 **>180s**
- ❌「角色卡 → 分镜脚本 → 分镜参考图 → 逐镜头生成 → 后期拼接」是 >15s 的必经流程
  → 前期设计（角色卡、分镜脚本）**仍然必要**，但"逐镜头生成 + 后期拼接"在 ≤180s 时可跳过

> ⚠️ 别过度反应：前期设计不是被 30 秒直出取代的。**概念不好，直出 30 秒只是把平庸拉长了 15 秒。**
> SKILL.md 开篇那句"先想清楚做什么，再考虑怎么写"在 2.5 下**更重要**，因为单次试错成本翻倍。

## 3. 时间戳 × 长时长 = 相乘，不是相加

这是 2.5 最值得学的东西。实测原文：

> 在 8 秒、十几秒的时长里写时间戳，你最多排两三个镜头，
> **30 秒配上时间戳，才第一次装得下一个完整的起承转合，这两个能力是相乘的。**
> …… 以前你写 prompt 是在向模型描述一个愿望，**现在你是在给它递一份导演的分镜表。**

官方 180 秒案例的写法：**每一段发生什么都写在同一条提示词里，用时间戳推进整个叙事**，
3 分钟跨度里角色特征、服装细节、场景建筑首尾一致。

### 30 秒时间戳分镜模板

```
[总时长][风格总纲 + 一句话贯穿性声明]，
[全片一致性锁定：角色特征 / 服装 / 场景，一句话写死]，

0-6秒：[画面 + 运镜 + 音效]；
6-12秒：[转场方式 + 画面 + 运镜 + 音效]；
12-19秒：[画面 + 运镜 + 音效]；
19-26秒：[画面 + 运镜 + 音效]；
26-30秒：[收束画面 + 定格]。

全程规范：[跨段一致性的硬约束 + 光线/色调的渐变规律]
```

**和 2.0 时间戳法的三点差异：**

1. **段数从 3–4 段变成 5–6 段**。30 秒按 5–7 秒一段切，每段装一个完整动作
2. **必须加"全片一致性锁定"句**。15 秒里角色不太会漂，30 秒会。开头把角色可辨识特征写死一遍
3. **必须加"全程规范"收束段**。跨 5 个时间段的光线/色调/运镜连续性，靠这一段兜底

### 实测通过的 30 秒范例（一镜到底 + 时代穿越）

> 来源：[优设网实测](https://www.uisdc.com/seedance-2-5-2)。
> 注意它同时用到了上面三个要点：一致性锁定（"全程体型羽色不变"）、5 段切分、全程规范收束。

```
30秒一镜到底，电影感，胶片颗粒质感，镜头全程与一只葵花鹦鹉同速贴身跟飞，无剪切，光线随时代自然过渡。
主角是同一只葵花鹦鹉：通体雪白，柠檬黄冠羽，全程体型羽色不变。
0-6秒：清晨薄雾的1900年代帆船港口，桅杆如林，鹦鹉从一根桅杆顶端起飞，镜头贴身跟上，掠过收起的船帆和绳索。
6-12秒：鹦鹉穿入一团白色晨雾，出雾时已是1950年代码头，蒸汽货轮鸣笛，吊机林立，码头工人推着货箱，鹦鹉低掠过泛着油光的水面。
12-19秒：鹦鹉振翅爬升，掠过一片脚手架，正在建造中的白色贝壳形建筑只完成一半，工人在钢架间作业，夕阳把钢架染成金色。
19-26秒：鹦鹉俯冲穿过两栋玻璃幕墙的间隙，幕墙反光扫过整个画面，出来时已是2026年的现代都市夜幕初降，玻璃高楼灯光渐次点亮，鹦鹉在楼宇间穿行。
26-30秒：鹦鹉减速滑翔，落在一处居民阳台的木栏杆上，柠檬黄冠羽唰地竖起，歪头看向镜头，画面定格。
全程规范：一镜到底无剪切感，运镜如纪录片跟飞般丝滑，四个时代的光线（晨雾青灰、正午灰黄、黄昏金、夜幕蓝）自然渐变，鹦鹉羽毛细节真实。
```

**手法拆解**：用一个贯穿主体（鹦鹉）当锚点解决跨段一致性 —— 这是 30 秒叙事最省力的结构。
时代/场景可以随便换，只要主体不变，观众就认为是"一镜到底"。

## 4. 50 个素材：分工声明从"建议"变成"生死"

2.0 最多 12 个素材，不说清用途也能蒙对。**30 张图不说清楚，参考必然互相打架。**

新增的硬要求：**每个素材必须点名用途**，且在提示词里显式引用。

```
@图片1-@图片6 → 主角六视图角色参考（只取外貌，不作首帧）
@图片7 → 首帧构图
@图片8-@图片20 → 场景/道具参考
@视频1 → 只借运镜和剪辑节奏，画面内容不复用
@视频2 → 动作迁移源
@音频1 → 主角音色
@音频2 → BGM
```

🔬 **待验证**：2.0 时代的经验是"同角色多张裁剪特写会打散身份信号"。
2.5 支持 30 张图之后，这条是否被推翻（比如六视图角色参考反而更强）？**这是第二个最值得实测的假设。**

## 5. 新输出形态：片段重拍指令

2.5 的"片段重拍"支持框选时间段 + 画面区域 + 提示词做**单秒级修改**，不重新生成整条视频。

这意味着改写器多了一种输出形态 —— **不是重写整条 prompt，而是写一条编辑指令**：

```
## 片段重拍指令

**时间段**：00:12 - 00:14
**框选区域**：画面右下角人物手部
**指令**：把手里的纸杯换成陶瓷马克杯，其余不变
**保持不变**：人物动作、镜头运动、光影、其余画面元素
```

三条纪律：

1. **必须显式写"保持不变"清单**，否则模型可能顺手改掉别的
2. **时间段尽量窄**。框 2 秒比框 10 秒准
3. **一次只改一件事**。要改三处就发三条，混在一起互相干扰

## 6. 审查变化（2.0 的 SOP 要扩展）

SKILL.md 里那套 v5 版权审查 SOP（5 条铁律 + 三层动作分级）**继续有效**，2.5 新增两条：

### 🚨 台词也过版权扫描

实测踩坑：台词里写了 `C'est la vie` 被拦，提示"输入文本可能涉及版权限制"——
**因为它是好多首歌的歌名**。

→ **写台词时要过一遍"这句话是不是某首歌/某部片的标题或名句"**。
中文里同理：「后来」「小幸运」「凡人歌」这类常见歌名当台词有风险。改成同义但非标题的说法。

### 🚨 真人脸规则变了：从"禁止"变成"需认证"

2.0 时代 SKILL.md 核心规则写的是「不得包含写实真人面部素材——平台会自动拦截」。

2.5 的实测反馈是：**未认证人脸不支持生成**，出于肖像保护，**认证后可以**。
连 AI 生成的人脸垫图也会被拒（"出于肖像保护考虑，未认证人脸不支持生成"）。

→ 新口径：**默认仍按"不用写实真人脸"处理**（多数场景用户没做认证）；
但如果用户明确说已完成人脸认证，这条限制可以放开，不要再机械拒绝。

## 7. 2.5 待验证清单（按优先级）

跑到就往 `experiments/cases/` 落一份，回来把 🔬 改成结论。

| # | 假设 | 怎么验 |
|:---|:---|:---|
| 1 | 2.5 弱化油腻感后，重美学约束（Octane/8K/工业光魔）从有用变有害 | 同概念两版对比：完整美学约束 vs 极简 |
| 2 | 30 张图的多图角色参考不再打散身份（推翻 2.0 结论） | 单张全身 vs 六视图，同角色同场景 |
| 3 | 30s 直出的一致性确实优于 2×15s 拼接 | 同剧情两种做法，比衔接处 |
| 4 | 长视频模式 180s 的实际一致性衰减曲线 | 跑一条 180s，记第几秒开始漂 |
| 5 | 平台侧延长 2 次（90s）的衔接质量 | 延长处是否有光影跳变 |
| 6 | 路径 C（图生视频）的 2000 字符上限在 2.5 是否变化 | Python `len()` 实测，**不准凭字感估算** |
